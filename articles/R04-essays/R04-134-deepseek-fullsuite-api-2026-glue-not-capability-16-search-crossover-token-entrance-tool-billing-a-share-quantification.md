# DeepSeek 全家桶 API：卖的不是能力，是那次握手

## 摘要

2026 年 11 月 13 日，DeepSeek 正式开放"全家桶应用 API"——在原有 API 中开启对应参数，即可获得联网搜索、深度思考搜索、文件输入、阅读链接、模型安全等对话能力；同时把 Search、Fetch、OCR、ASR、TTS 开放为独立接口。V4.1-Flash（deepseek-flash）已在 Messages、Responses、Chat Completions 三种接口下支持，且工具调用与上下文拼接均由服务端自动完成。除 Token 费外，工具按次单独计费：搜索与抓取 5 元/千次、OCR 1.5 元/千页、ASR 0.39 元/小时、TTS 1.5 元/万字符，语音类限时 5 折。

市场的主流解读是"DeepSeek 补齐了 Agent 工具链，降低开发门槛"。本报告认为这个解读漏掉了它真正在做的事。

核心判断是：它卖的不是任何一个单项能力，是"工具与模型之间的那次握手"。因为搜索、OCR、ASR 这些能力市场上早就有，甚至更便宜的也有——真正昂贵的，从来不是"能力本身"，是"能力与模型推理之间那层胶水"：调用衔接、上下文拼接、异常兜底、引用对齐。而它做的事，是把这层胶水压缩成了一个参数。

由此展开三条判断：

第一，这是"平台化"的最高形态——把自己的成品，降级成别人的原料。官方自己写得很清楚："DeepSeek 现有的对话产品只是较为基础的一种形态。"这句话的潜台词是：我不是要做一个最好的 App，我是要提供"做 App 的所有零件"。

第二，定价设计是"吉列模式"的 AI 版：Token 是入口，工具按次是收钱。因为"每百万 Token 2 元"这种数字最适合传播，而"5 元/千次搜索"才是真正随用量增长的部分。

第三，关于它与英伟达权力交接的"共振"，需要修正一个流行假设——黄仁勋真正稀缺的不是"立场温和"，是"愿意花政治资本"。而"缓冲"是一种消耗品，创始人愿意持续投入，职业经理人不会。

本报告在其上补四个原文没有的算术视角：其一，"每任务 16 次搜索"是这个算例的成本结构反转临界点——低于 16 次 Token 费占主导，高于 16 次工具费占主导；其二，若上下文真实累积，5 轮输入不是 20K 而是 30K tokens，Token 费从 0.08 元升到 0.10 元，工具费超出幅度由 56% 降到 25%（结论不变但幅度要改）；其三，Token 费对"轮数 × 上下文"呈超线性、工具费对"调用次数"呈线性，所以"减少轮数"比"减少搜索"更能省钱；其四，语音定价存在一个被忽略的不对称——同样一段文字，"读出来"比"听写成文字"贵约 4.6 倍。

## 核心参数

### 表 1：发布坐标

| 项目 | 内容 |
|------|------|
| 发布日 | 2026 年 11 月 13 日 |
| 形态 | 在原有 API 中开启对应参数 |
| 内置对话能力 | 联网搜索、深度思考搜索、文件输入、阅读链接、模型安全 |
| 独立接口 | Search、Fetch、OCR、ASR、TTS |
| 模型 | V4.1-Flash（deepseek-flash） |
| 兼容接口 | Messages、Responses、Chat Completions |
| 关键承诺 | 工具调用与上下文拼接由服务端自动完成 |
| 附赠 | 开源轻量前端 Demo（chat-demo），支持导入历史对话 |

这张表的最后一行最容易被当成"赠品"忽略掉。但它恰恰是整篇公告里最能说明态度的证据：连界面都开源了，潜台词是"你只需要写业务"。而"你只需要写业务"这句话，正是平台化的标准句式——因为它把"做产品"这件事里所有不属于你的部分，都替你做了。

### 表 2：一个参数替代了什么

| 环节 | 11 月 13 日之前需要对接的东西 |
|------|------------------------------|
| 对话与推理 | 模型 API |
| 联网搜索 | 搜索服务商 |
| 网页抓取 | 自建爬虫或第三方抓取 |
| 文件解析 | PDF / Office 解析库 |
| OCR | 图像文字识别服务 |
| 语音输入 | ASR 服务 |
| 语音朗读 | TTS 服务 |
| 内容安全 | 审核服务 |
| 胶水层 | 调用衔接、上下文拼接、异常兜底、引用对齐 |

九个环节里，前八个是"可以买到的能力"，第九个是"必须自己写的活"。而这一次发布真正改变的，是第九个——"在原有 API 中开启对应参数，即可获得……相关工具调用与上下文拼接均由服务端自动完成"。所以准确的描述不是"多了几个 API"，而是：它把"系统集成"这个环节，压缩成了一个开关。

### 表 3：自建与全家桶的成本对照

| 方案 | 你要买什么 | 你要做多少"胶水工作" |
|------|-----------|---------------------|
| 自建 | 模型 + 搜索 + 抓取 + 解析 + 审核 | 串起 5 个供应商、写对接、处理超时、对齐引用 |
| 全家桶 | 一个 API Key + 一个参数 | 写业务逻辑本身 |

注意右列的区别：自建那一列列的是"四类工作"，全家桶那一列只有一项"写业务逻辑本身"。所以它真正降低的不是"单价"，是"集成复杂度"。而"集成复杂度"在 Agent 时代有一个很特殊的性质：它不体现在账单上，体现在"工期"上——而工期，恰恰是创业公司最贵的成本。

### 表 4：四个竞争维度的状态

| 维度 | 现在的竞争状态 |
|------|---------------|
| 模型跑分 | 差距在缩小，且大部分场景感知不到 |
| API 价格 | 已经卷到极低 |
| 工具链完整度 | 差距明显，且直接影响能否交付 |
| 胶水成本 | 完全没被标准化 |

四行里前两行已经是"红海"，第三行是"有差距但可追"，第四行是"完全空白"。而这张表最重要的读法，不是"第四行有机会"，而是"前两行已经不再是差异化的来源"。所以标题那句判断可以写得更硬：在 Agent 时代，最值钱的不是"最强的模型"，也不是"最便宜的 API"，是"最少的胶水"。

### 表 5：常规做法与 DeepSeek 的做法

| 常规做法 | DeepSeek 的做法 |
|---------|----------------|
| 把 App 做成最好的产品 | 把 App 拆成"做产品的零件" |
| 让用户留在我的 App 里 | 让开发者用我的零件做他们自己的 App |
| 竞争"谁的产品更好" | 竞争"谁的零件被更多人用" |

三行对照，指向同一句话：这是"平台化"的最高形态——把自己的成品，降级成别人的原料。而它的战略含义在于"定义权"：因为定义零件的人，定义了产品的上限。过去定义"一个好用的 AI 应用"的是产品经理、大厂、排行榜；而现在，"一个 App 由哪些参数组成"，是被 API 定义者写下的。

而这件事最难被追赶：因为"做得更好"是渐进式的，"重新定义零件"是跳跃式的。而后者一旦被接受，前者就只能在这个框架里做优化。这就是为什么"平台化"比"产品化"更狠——不是因为它更难做，是因为它一旦成立，就把对手的努力方向都变成了"在你的框架里优化"。

| 项目 | 原文口径 | 累积口径 |

| 工具费 | 0.125 元 | 0.125 元 |
| 工具费 / Token 费 | 1.56 倍 | 1.25 倍 |

这里必须做一处修正，因为它是全篇最容易被"算错"的地方。原文的算法是"5 ×（4K × 2 + 1K × 8）÷ 1M"，隐含假设是"每轮 4K 输入不含历史"。但真实的多轮 Agent 是累积的：第 1 轮 4K、第 2 轮 5K、第 3 轮 6K、第 4 轮 7K、第 5 轮 8K，合计 30K。这样 Token 费从 0.08 元升到 0.10 元。

## 一、先把"多了一个 API"这件事说准确

讨论这件事，最容易停在"DeepSeek 补齐了工具链"。但请先看它到底把什么变成了"一个参数"。

在 11 月 13 日之前，一个开发者想"复刻一个 DeepSeek App"，需要对接九样东西：模型 API、搜索服务商、自建爬虫或第三方抓取、PDF/Office 解析库、图像文字识别服务、ASR 服务、TTS 服务、审核服务，以及最后那层"胶水"——调用衔接、上下文拼接、异常兜底、引用对齐。

而在 11 月 13 日之后，官方文档的原话是："在原有 API 中开启对应参数，即可获得……开启对应参数后，相关工具调用与上下文拼接均由服务端自动完成。"

所以这次发布的准确描述不是"多了几个 API"，而是：它把"系统集成"这个环节，压缩成了一个开关。

而这就是本文的第一个判断：它卖的不是"搜索能力"，是"那次握手"。因为搜索能力本身早就不是稀缺品；而"让搜索结果正确地进入模型上下文、并且带着可用的引用"这件事，才是每个 Agent 开发者都要重复做一遍的苦活。而这个苦活的成本，不在账单上，在工期上。

## 二、核心判断："最少的胶水"才是 Agent 时代的稀缺品

这一节是全文的分析支点。

先做成本对照。假设你要做一个"会查资料的研究助手"：自建方案要买模型、搜索、抓取、解析、审核，并且要串起 5 个供应商、写对接、处理超时、对齐引用；全家桶方案只要一个 API Key 加一个参数，剩下的时间是"写业务逻辑本身"。

所以它真正降低的，不是"单价"，是"集成复杂度"。而"集成复杂度"在 Agent 时代有一个很特殊的性质：它不体现在账单上，体现在"工期"上。而工期，恰恰是创业公司最贵的成本。

而这引出四个竞争维度：模型跑分——差距在缩小，且大部分场景感知不到；API 价格——已经卷到极低；工具链完整度——差距明显，且直接影响能否交付；胶水成本——完全没被标准化。

前两行是红海，第三行有差距，第四行是空白。所以"跑分"和"价格"都已经不是差异化的来源了，剩下的是"能不能一次交付"。而 DeepSeek 这次做的，正是把"胶水"标准化。

在 Agent 时代，最值钱的不是"最强的模型"，也不是"最便宜的 API"，是"最少的胶水"。

## 三、最值得说的一句官方话："官方产品只是较为基础的一种形态"

这一节的证据，来自公告原文，而且是两部分。

第一部分是公告的"写在后面的话"："我们相信，人与模型的交互依然充满无限可能，而 DeepSeek 现有的对话产品只是较为基础的一种形态。"第二部分是同一处的另一句："现在，官方产品背后的各项能力均已支持通过 DeepSeek API 随心调用、自由组合。"

两句话合起来，说的是一件很反直觉的事：它把自己的成品 App，定位成了"一个示例"，而不是"一个终点"。

这是一个极高的战略姿态。因为常规做法是"把 App 做成最好的产品、让用户留在我的 App 里、竞争谁的产品更好"；而它的做法是"把 App 拆成做产品的零件、让开发者用我的零件做自己的 App、竞争谁的零件被更多人用"。

这就是"平台化"的最高形态：把自己的成品，降级成别人的原料。而它的战略含义是深远的：因为"定义零件"的人，定义了"产品"的上限。过去，谁能定义"一个好用的 AI 应用"？是产品经理、是大厂、是应用商店的排行榜。而现在，"一个 App 由哪些参数组成"，是被 API 定义者写下的。而这恰恰是最难被追赶的地方：因为"做得更好"是渐进式的，"重新定义零件"是跳跃式的。而后者一旦被接受，前者就只能在这个框架里做优化。

顺带说一个很实在的细节：官方同时开源了一份轻量前端 Demo（chat-demo），支持直接导入 DeepSeek 历史对话。这个动作的潜台词是："连界面我都给你了，你只需要写业务。"

## 四、定价的真相：Token 是入口，工具按次是收钱

这一节讲商业模式，而证据是那张价格表。

模型侧：工作日高峰输入 2 元/百万 tokens、输出 8 元/百万 tokens，其他时段半价。工具侧：搜索（文字/图片）5 元/千次、网页抓取 5 元/千次、OCR 1.5 元/千页、ASR 0.39 元/小时（限时 5 折）、TTS 1.5 元/万字符（限时 5 折）。

这里有一个非常精巧的设计："每百万 Token 2 元"这种数字，最容易传播、最容易做对比、最容易让人记住"便宜"；而"5 元/千次搜索"——也就是每千次调用 5 元——才是随用量增长而真正放大的部分。

用原文的示意算例算一遍：一个"重度搜索"的研究型 Agent，一次任务 5 轮、每轮搜索 5 次（共 25 次），每轮输入 4K tokens、输出 1K tokens。Token 费约 0.08 元，搜索费约 0.125 元。在这个例子里，工具费已经超过了 Token 费。

而这里必须补三点原文没有的算术。

第一，反转临界点。Token 费在这个架构下是固定值 0.08 元；搜索费是"次数 × 0.005 元"。两者相等时，次数 = 0.08 ÷ 0.005 = 16 次。所以结论可以写得更精确：每任务少于 16 次搜索，Token 费占主导；多于 16 次，工具费占主导。这个临界点比任何一句"便宜"或"贵"的评价都更有用，因为它把"贵不贵"变成了"你的架构属于哪一类"。

第二，上下文累积的修正。原文的算法隐含"每轮 4K 输入不含历史"。但真实多轮 Agent 是累积的：4K + 5K + 6K + 7K + 8K = 30K，Token 费从 0.08 元升到 0.10 元，工具费对 Token 费的倍数从 1.56 降到 1.25。结论不变，但幅度要改——而更重要的是这个修正揭示的非线性：**Token 费对"轮数 × 上下文"是超线性的，工具费对"调用次数"是线性的。** 所以"把 5 轮压到 3 轮"比"把 25 次搜索压到 15 次"更能省钱。

第三，跨模态的比价。一次搜索 5 厘，而 1K 输入 tokens 是 2 厘——所以"搜一次"约等于"读 2.5K tokens 的输入"。这个换算让开发者第一次可以把"检索"与"阅读"放在同一个尺度上取舍。同理，一次 OCR 一页 1.5 厘，约等于"读 0.75K tokens"；所以"多扫描一页"的边际成本，其实比"多读半页文本"更低。

而这三个算术合起来指向一个结论：在"重度工具调用"场景里，成本结构会反转；而在"轻度对话"场景里，成本几乎全是 Token 费。而这正是"吉列模式"的 AI 版本——便宜的入口（Token 单价）换装机量，持续的消耗（工具调用次数）换收入。

而它并不"隐瞒"这件事——官方公告明确写了"除收取 Token 费用外，也将收取相关工具的调用费用"。它只是让"便宜"的部分更容易被传播。而这对开发者的实际含义是：不要只看 Token 单价，要算"你的 Agent 每次任务会调用多少次工具"。因为"你的成本，取决于你的架构"——一个"每轮都搜"的 Agent，和一个"先规划再搜"的 Agent，成本可能差好几倍。

## 五、一个被忽略的战略细节：它走了"两步"

DeepSeek 并不是一次性把能力全放出来的。据阿里云开发者社区报道，Search 与 Fetch 两个搜索接口在上个月（10 月）就已经开放过；而这次（11 月 13 日）新增的是"对话里的内置联网工具、文件输入、OCR、语音和安全审核"。

把两步放在一起看，会发现一条很清晰的路径：第一步（10 月）开放 Search、Fetch 独立 API，性质是"原子能力"（零件）；第二步（11 月 13 日）开放内置工具 + 文件 + OCR + 语音 + 安全，性质是"编排能力"（整机）。

先给"零件"，再给"整机"——这是一个非常聪明的顺序。因为先开放"零件"，可以让开发者"按自己的方式组装"，从而验证"零件好不好用"；再开放"整机"，可以让不想组装的开发者"直接用"，从而吃到"最大公约数"的需求。

而这两步合起来，覆盖了全部开发者：有自己工作流的团队要"零件"（被第一步覆盖）、想快速验证的团队要"整机"（被第二步覆盖）、两者都要的团队混用（两步都覆盖）。而"两步都覆盖"这件事，恰恰是平台化的关键——因为一个平台，如果只能服务一种开发者，它就长不大。

## 六、关于"与英伟达共振"：需要修正一个流行假设

这一节处理一个外部推断，我认为它需要被校正。

常见的推论是："黄仁勋是英伟达内部对华业务、出口管制弹性的关键缓冲人；市场普遍预期继任管理层会更贴合美国监管鹰派路线。"

这个推论方向合理，但它把"缓冲"理解成了"立场"。而我认为更准确的理解是"成本"。

黄仁勋真正稀缺的东西，不是"他亲华"，是"他愿意花政治资本"。因为"缓冲"这件事，从来不是一句表态，而是一连串具体动作：反复去华盛顿沟通、在国会听证中承担质询、用个人声誉为一笔交易背书、长期投入时间而不是一个季度。而这些事，一个 CFO 出身的临时 CEO，最不可能做——因为她要对"合规风险"负责，而不是对"市场份额"负责。

所以更准确的判断是：不是"继任者一定更鹰"，而是"继任者一定更少去争论"。

而"更少争论"在结果上，可能等同于"更严格的执行"——但它不是"主动收紧"，是"不再主动放松"。这个区别对判断很重要：如果继任者"更鹰"（主动收紧），会出现"新的限制措施"；如果继任者"更少争论"（被动执行），只是"旧的弹性不再被使用"。而后者更隐蔽，也更难被对冲——因为它不是"一个新政策"，是"一个旧空间消失了"。

而这恰恰抬高了"多底座兼容"的战略价值：因为当"弹性"不再来自"某个人愿意争取"，它就只能来自"你本来就不依赖它"。

而 DeepSeek 这条路线，做的正是这件事：据报道，其模型原生适配昇腾与英伟达双平台；而现在把应用层工具链也打包成 API——于是"算力底座的选择"被藏在了 B 端接口之后。对开发者而言，底层是英伟达还是国产 NPU，是透明的。所以"算力供给的不确定性越高，上层接口标准化、算力底层无感，这条路越值钱"。

## 七、中国的优势不在"跑分"，在"场景密度"

这一节是本文最想给出的判断。

很多人把 AI 竞争理解成"谁的模型更强"。但这个框架有一个隐含前提：它假设"强"是一个绝对标准，而且"强"能直接转化为"用"。而在 Agent 时代，这个假设正在被动摇：模型从"跑分"变成"够用"，工具链从"自己接"变成"厂商给"，算力从"买最强的"变成"多底座兼容"，交付从"拼装"变成"一体化"。

而"栈完整"这件事，需要的不是"最先进的光刻机"，是"最丰富的场景"。而这恰恰是中国的结构性优势：场景密度（最完整的产业门类、最多的中小企业）、开发者密度（最庞大的应用开发群体）、迭代速度（最快的试错与反馈循环）、工程能力（最擅长"把复杂系统做便宜"）。

所以"模型跑分"是需要制程的，而"栈完整"是需要场景的。前者我们还在追，后者我们本来就有。而这也解释了为什么这次发布的姿态是"开放零件"而不是"发布最强模型"：因为当"模型能力"逐渐同质化时，胜负手就从"谁的模型更强"，挪到了"谁能让别人更快地做出东西"。

## 八、四个需要校正的认知

**一、"这只是多了几个 API"是误读。** 它把"系统集成"压缩成了一个参数——降低的不是单价，是"工期"，而工期是创业公司最贵的成本。

**二、"Token 便宜 = 用起来便宜"是误读。** 除 Token 费外，还有工具调用费。在重度工具调用场景里，工具费可能超过 Token 费——而且临界点是"每任务 16 次搜索"。成本取决于你的 Agent 架构，而不是模型单价。

**三、"它要和自己的 App 竞争"是误读。** 官方明确"现有的对话产品只是较为基础的一种形态"——它把 App 定位成"示例"，而不是"终点"。这是平台化，不是产品化。

**四、"黄仁勋离职 = 继任者一定更鹰"是过度推断。** 更准确的是"继任者一定更少去争论"——而这在结果上表现为"旧的弹性不再被使用"，不是"新的限制被主动推出"。

## 九、六个可以跟踪的观察指标

第一，**"工具调用费 ÷ Token 费"在真实 Agent 应用里的比值分布，而不是"每百万 Token 多少钱"**。这是本文最看重的指标——因为 Token 单价是"入口定价"，用来传播；工具费是"用量定价"，用来收钱。而这个比值，决定了"谁在真正为 AI 付费"——是聊天的人，还是跑 Agent 的企业。

第二，**工具调用在总调用中的占比（工具渗透率）**。因为如果它长期很低，说明大家还是把它当"聊天 API"用；只有它显著上升，才说明"Agent 化"真的发生了。

第三，**开发者是"用整机"还是"用零件"**。因为"只用整机"说明它在做产品，"混用零件与整机"才说明它在做平台。

第四，**是否出现"基于这套工具协议"的第三方生态（模板、SDK、垂直方案）**。因为平台化的标志不是"官方有多少能力"，是"别人在它之上做了多少东西"。

第五，**国产算力上的"可复现性"**：同样的全家桶功能，在昇腾等平台上是否功能一致、延迟可接受。因为"无感"是这套路线的核心承诺——而"无感"必须被验证，不能只被宣布。

第六，一个反直觉但最本质的指标：**看 DeepSeek 是否继续"开源自己的 App 实现"，而不是只开源 SDK**。因为"开源成品"这个动作，比任何一句"我们做平台"都更能证明它真的不在乎"用户留在我的 App 里"。一个愿意把自己的产品变成别人起点的公司，才是在做平台。

## 十、结论：从"卖能力"到"卖接口"

回到这次发布。它表面上是一次 API 的扩容，实质上有三层含义：产品上，它把"系统集成"压缩成一个参数，卖的其实是"工具与模型之间的那次握手"；战略上，它把自己的成品 App 降级为"零件供应商"，这是平台化的最高形态；商业上，它用"Token 便宜"做入口、用"工具按次"做收入，是吉列模式的 AI 版。

而把这三层合起来，会得到一个更本质的判断：AI 产业的竞争，正在从"卖能力"，转向"卖接口"。卖能力的计量单位是 Token 与调用次数，卖接口的计量单位是"别人做了多少东西"；卖能力的客户关系是"采购关系"，卖接口的客户关系是"依赖关系"；卖能力的护城河是"性能领先"，卖接口的护城河是"生态惯性"；而最终能赢的，不是"模型最强的"，是"最被组装的"。

而"卖接口"这件事，有一个很反直觉的特点：它要求你先接受"自己不是终点"。

最后，回到一个更朴素的层面。在讨论 AI 竞争时，最容易陷入的叙事是"追赶与被追赶"。但这次发布提示了另一种可能：在一个"能力正在快速同质化"的市场里，决定胜负的往往不是"谁最强"，而是"谁最先让别人用起来"。而"让别人用起来"这件事，需要的不是更强的模型，是更少的摩擦。而这，恰恰是中国工程能力最擅长的事：我们不一定是那个"发明零件"的人，但我们可以是那个"把零件做得又好又便宜、还顺手帮别人装好"的人。而在产业链上，后一种角色往往拿得更久——因为它离"使用"更近。

**第二，与市场流行认知的错位在科大讯飞这只标的上。** 市场看到"ASR/TTS 开放为独立接口"，第一反应是"语音龙头受益"。但把价格摆出来看：ASR 0.39 元/小时、TTS 1.5 元/万字符——这等于给这个行业定了一个公开的价格锚。这是"利好行业、利空公司"的典型场景：需求确实增加，但价格被第三方锚定，公司失去了自主定价的空间。科大讯飞综合分 6.19 排第七，而它通常是这条线里被第一个想起的标的。这个错位提醒一件事：**平台开放能力，受益的是"用能力的人"，不是"卖能力的人"。**

**第三，方向内部的离散度揭示了三种不同的风险。** 国产算力底座 5.91–6.80，宽度 0.89，最大——说明"故事型"标的与"订单型"标的的差距会持续拉开，这条链是靠 D 分（订单可见度）分化的。Agent 应用层 5.95–6.26，宽度 0.31；平台型生态 6.43–6.79，宽度 0.36；多模态数据与语音 5.94–6.19，宽度 0.25，最窄——最窄的这条链恰恰说明它被同一个定价锚压住，缺乏内部alpha，只能同涨同跌。

## 结论

这次发布有四个数字必须重新读。0.08 元与 0.125 元不是"谁更贵"，而是"两种成本结构的对撞"——它们在每任务 16 次搜索处交叉。5 元/千次不是一个小数字，它相当于 2.5K 输入 tokens 的价格，所以"搜一次"和"读两页半"是等价的。1.5 元/万字符与 0.39 元/小时构成的 4.6 倍不对称，说明语音这门生意"听便宜、说贵"，而这由"生成是自回归解码、识别是一次前向"决定。而 4 倍的输入输出价差（2 元与 8 元）反而是最不重要的那个数字，因为它最容易被比较，也最容易被卷平。

产品上，它把"系统集成"压缩成一个参数，卖的其实是"工具与模型之间的那次握手"——因为搜索、OCR、ASR 早就不稀缺，真正昂贵的是调用衔接、上下文拼接、异常兜底、引用对齐这四件事。战略上，它把自己的成品 App 降级为"零件供应商"，这是平台化的最高形态，因为定义零件的人定义了产品的上限。商业上，它用"Token 便宜"做入口、用"工具按次"做收入，是吉列模式的 AI 版。

而这三点合起来，指向一个更本质的判断：AI 产业的竞争，正在从"卖能力"转向"卖接口"。卖能力的护城河是性能领先，卖接口的护城河是生态惯性——而生态惯性比性能领先更持久，因为它不依赖"每年都更强"。

最后一句给从业者：在一个能力快速同质化的市场里，决定胜负的往往不是"谁最强"，而是"谁最先让别人用起来"。而让别人用起来需要的不是更强的模型，是更少的摩擦。我们不一定是那个"发明零件"的人，但可以是那个"把零件做得又好又便宜、还顺手帮别人装好"的人——而在产业链上，后一种角色往往拿得更久，因为它离"使用"更近。

### A2 三个关键概念界定

**其一，"胶水层"与"能力层"。** 本文的"能力层"指可被单独采购的功能（搜索、OCR、ASR、TTS）；"胶水层"指把这些能力接入模型推理所需的工程工作（调用衔接、上下文拼接、异常兜底、引用对齐）。两者的关键区别是：能力层可以按次计价、可以比价、可以被替代；胶水层按工期计价、无法比价、且每个团队都要重复做一遍。本文判断的核心正在于——平台化的价值不在能力层，在胶水层。

**其二，"入口定价"与"用量定价"。** 前者指设计用来被比较、被传播、被记住的价格（如每百万 Token 2 元）；后者指随真实使用量线性放大、且缺少可比参照的价格（如 5 元/千次搜索）。本文用这一对概念解释"为什么最便宜的那个数字不是最重要的那个数字"。

**其三，"平台化"与"产品化"。** 产品化是"把成品做到最好并留住用户"，平台化是"把成品拆成零件并让用户离开"。本文采用的是最严的判据：不以"开放了多少接口"为标准，而以"是否开源自己的成品实现、是否出现第三方生态"为标准。按这个判据，本次发布迈出了平台化的关键一步，但"平台"是否成立，仍要看第三方生态。

### B3 三条原则

**其一，"位置"优先于"能力"。** 本模型在给 D 与 P 打分时，先判断公司处在"定义零件"、"提供底座"、"使用零件"还是"被零件替代"的哪个位置。前两者加分，后两者减分。这条原则直接来自本文的核心判断：当能力被 API 化并公开定价后，卖能力的一方失去定价权，用能力的一方获得成本优势。科大讯飞 D 分 6.2 但 V 分仅 5.2 的组合，就体现了"能力被公开锚价"对这一位置的压力。

**其二，估值分是对称的约束而不是单向的加分。** V 分高不代表看好，只代表当前价格相对历史与同业不贵；V 分低会被扣分，但不会因为"赛道好"而被豁免。海光信息 G 分 7.4 而 V 分仅 4.8，就是这个原则的体现——空间大不能抵消估值满。

**其三，评分只描述竞争位置，不描述股价路径。** 综合分衡量的是"这个事件对该公司竞争位置的边际影响"，不是"未来 12 个月的预期收益率"。事件仓与底仓的久期错配、市场预期是否已反映、流动性结构，都不在本模型内。对多模态方向尤其要注意：它的核心矛盾是"量的增速能否超过价的降幅"，这个矛盾在季度数据里可能长期不可见。
